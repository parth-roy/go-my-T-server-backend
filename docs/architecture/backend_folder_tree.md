# Parther Logistics Backend Directory Structure

Below is the exhaustive folder structure for the backend (`server`) directory, along with a brief explanation of each directory's role in the architecture.

```text
server/
├── .vscode/               # Editor configurations (formatters, debuggers)
├── audit/                 # Security, performance, and architecture audit reports
│   └── 2026-07-11-backend/# Contains the findings from the last major security audit
├── dist/                  # Compiled JavaScript output (generated by TypeScript)
├── docs/                  # Exhaustive Markdown documentation (API, Architecture, Modules)
│   ├── api/               # Complete API endpoint references (grouped by batch)
│   ├── architecture/      # Architectural guidelines (Auth, Realtime flows)
│   ├── modules/           # Module-level documentation (Responsibilities, Business logic)
│   └── services/          # Service-level granular code mapping
├── prisma/                # Prisma ORM Configurations
│   └── migrations/        # SQL Migration history (managed by Prisma)
├── scripts/               # Helper scripts (deployment, DB reset, log analysis)
├── src/                   # Main TypeScript Source Code
│   ├── config/            # Environment variable validation (`env.ts`) and global config
│   ├── database/          # Database seeding scripts (e.g., `seed-pricing.ts`)
│   ├── modules/           # Feature Modules (Domain-Driven Design)
│   │   ├── admin/         # Super-admin controls and pricing overrides
│   │   ├── announcement/  # System-wide broadcast alerts
│   │   ├── auth/          # Authentication (OTP, JWT, Refresh)
│   │   ├── booking/       # Core logistics booking flow & state machine
│   │   ├── contact/       # Support ticketing and contact forms
│   │   ├── dispatch/      # Auto-assign routing engine (nearest driver algorithm)
│   │   ├── driver-wallet/ # Driver earnings, payouts, and ledger
│   │   ├── fleet/         # Fleet vehicle management and verification
│   │   ├── fleet-owner/   # Fleet company controls and driver assignments
│   │   ├── fleet-wallet/  # Master wallets for fleet businesses
│   │   ├── gamification/  # Tier logic, points, and driver badges
│   │   ├── gig/           # Short-term jobs and task fulfillment
│   │   ├── leads/         # B2B sales pipeline and prospect tracking
│   │   ├── maps/          # Mapbox geocoding, routing, and search history
│   │   ├── marketplace/   # Private Bid marketplace (customer/driver negotiation)
│   │   ├── notifications/ # Push notifications (FCM) & In-app alerts
│   │   ├── payment/       # Razorpay integration and checkout sessions
│   │   ├── pricing/       # Dynamic fare calculation (base + distance + surge)
│   │   ├── rewards/       # Loyalty programs and customer discounts
│   │   ├── subscription/  # SaaS recurring billing (Basic vs Standard)
│   │   ├── support/       # Customer service chat / ticket handling
│   │   ├── tracking/      # Real-time GPS ingest and historical breadcrumbs
│   │   ├── training/      # Driver onboarding materials and videos
│   │   ├── ulip/          # Gov APIs (VAHAN/SARATHI/FASTAG/DigiLocker)
│   │   ├── upload/        # AWS S3 integration (POD, KYC documents)
│   │   ├── user/          # Core User profiles and preferences
│   │   ├── wallet/        # General customer wallet (top-ups)
│   │   ├── webhooks/      # External callbacks (Razorpay, ULIP async)
│   │   └── workforce/     # Labour/Helper allocation for heavy loads
│   ├── shared/            # Shared cross-module resources
│   │   ├── db/            # Initialized Prisma client singleton
│   │   ├── errors/        # Custom AppError classes & global error handlers
│   │   ├── eventbus/      # Global in-memory pub/sub (`TypedEventEmitter`)
│   │   ├── jobs/          # Node-cron background jobs (cleanup, reminders)
│   │   ├── logger/        # Winston / Pino structured logging setup
│   │   ├── middleware/    # Express interceptors (auth, roles, validation)
│   │   ├── payments/      # Shared payment gateways adapters
│   │   ├── queue/         # BullMQ configurations (producers)
│   │   │   └── workers/   # BullMQ consumers (background processing)
│   │   ├── redis/         # Upstash Redis client configuration
│   │   ├── services/      # Generic utility services (e.g., Mailer, SMS)
│   │   ├── socket/        # Socket.IO instance, namespaces, and rooms
│   │   ├── types/         # Global TypeScript interfaces and generic types
│   │   └── utils/         # Pure helper functions (math, string formatting)
└── test/                  # E2E test suites, contract tests, and Jest config
```
